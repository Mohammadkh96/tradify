Please review these exact requirements against Journal's current contract and implementation:

1. Each logical revocation has one permanent, immutable event ID.
2. The event payload remains identical across every delivery attempt.
3. The payload is canonicalized using JCS, with a stable hash persisted alongside the event.
4. Each retry generates a fresh RS256 assertion with a unique jti and a 120-second validity period.
5. Journal and Signals independently verify signature, pinned kid, issuer, audience, expiry and replay protection.
6. Idempotency is based on event ID and canonical payload hash, never on JWT jti or signature.
7. A repeated event with the same ID and payload hash receives an idempotent acknowledgment without repeating side effects.
8. Reusing an event ID with a different payload/hash returns HTTP 409 and produces a security audit record.
9. Revocation acknowledgments must match the original event ID and payload hash.
10. The local link remains unusable and revocation_pending until valid acknowledgment.
11. Transient delivery failures use bounded exponential backoff with a finite configured base and cap. Production retry parameters are not approved yet.
